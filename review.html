faham.复核台 · REVIEW DESK

这个页面把两条待审来源摊开：机器人候选（data/candidates/ 里的新闻线索）与 投稿队列（读者提交、存在数据库里的待审记录）。它们都还不是档案。
页面不会写入 data/events.json——它只帮你把字段拼成一份合乎结构的 JSON， 复制走之后，仍然由你自己粘进文件、自己 commit。这是起草台，不是后台管理系统： 发布这一步留在人手上和 git 记录里，是 docs/governance.zh.md 要求的，不该被一个网页绕过。

复核凭证

输入 REVIEW_TOKEN。凭证只存在 sessionStorage——关掉这个标签页就没了， 不会留在这台设备上。所有接口调用都带 Authorization: Bearer …。

机器人候选

机器人抓到的只是标题。标题不是事实，也不是「主张」—— 每条候选都带 headline_is_not_a_claim。 转成条目时，标题只能进 来源，不能被抄成正文。

投稿队列

拒绝与退回必须写理由：这个档案公开自己的拒稿记录。 没有理由的拒绝，等于没有规则。

条目编辑器

产出一份 data/events.json 结构的对象。 按 Esc 关闭。

收录准则自检

这是起草时的提醒，不是关卡——不达标也能复制。 真正的门槛在复核流程与 check_publishable()， 不在这个页面。
